# ОТЧЁТ по игре «СТАЯ» (Flock)

*Задача:* за 2 часа с нуля разработать качественную, оригинальную и «залипательную»
игру для Roblox (Luau).
*Старт:* 18.10.2026, 10:05:35 UTC. *Дедлайн:* 12:05:35 UTC.
*Репозиторий:* `github.com/ovococjsjs-gif/workspace`, ветка `arena/8b2d86db-workspace`.

---

## 0. Коротко

Игра **«СТАЯ»**: игрок ведёт стаю из 18 птиц через кольца-ворота. Кольцо
засчитывается, только если его прошла **вся стая** (после пересечения вожаком
открывается ограниченное окно). Потерянных птиц нужно подобрать и вернить в
строй. Четыре фазы (Штиль → Ветер → Скалы → Буря), комбо ×1…×5, рекорд в
DataStore с серверной проверкой правдоподобности.

Главная находка проекта — механика **«спокойствия стаи»**: резкое управление
вожаком пугает стаю, птицы вырываются из строя, кольца перестают проходиться
«чисто». Это превращает «веди кайт аккуратно» из лозунга в реальный навык с
визуальной шкалой в HUD.

Ключевые механики, которые добавились в итерации: **«рывок»** (ЛКМ — короткое
ускорение вожака ценой отвалившейся стаи), **«магнит»** (потерянная птица сама
тянется к вожаку, если он рядом) с маячком и стрелкой на экране, и
**«затишье»** (ветер стихает, когда стая на грани развала — второй шанс).

Ключевое архитектурное решение: **вся симуляция — чистый Luau без
Roblox-API**. Roblox-слой только рисует и читает ввод. Благодаря этому всю
механику удалось покрыть автотестами и прогонами в консоли — без Studio.

### 1.3. Клиент и сервер (Roblox-слой)

* `src/client/Main.client.luau` — цикл: ввод → `Game.step` → события → HUD/Views/Audio;
  камера следует за вожаком; стандартный персонаж скрывается; рекорд через
  RemoteEvent.
* `src/client/Views.client.luau` — вожак (неоновый шар + нимб + Trail), 18 птиц
  с взмахом крыльев и миганием потерянных, кольца из 12 сегментов с
  полупрозрачной мембраной.
* `src/client/HUD.client.luau` — счёт, рекорд, комбо, «СТАЯ 18/18» с полосой,
  **«СПОКОЙСТВИЕ» с полосой**, окно кольца, виньетка опасности, тосты, экраны
  старта/финала. Весь HUD строится кодом — в репозитории нет ни одного
  Gui-объекта.
* `src/client/Audio.client.luau` — звуки через `rbxasset://sounds/*` (всё в
  `pcall`, отсутствие ассета не ломает игру), отдельный крик паники.
* `src/server/Main.server.luau` — DataStore `flock_best_v1`, отдача рекорда
  клиенту, **серверная** проверка правдоподобности счёта; длительность забега
  считает сам сервер (`os.clock()`), чтобы клиент не мог её накрутить.
* `default.project.json` — манифест Rojo: `ReplicatedStorage.FlockShared`,
  `ServerScriptService.FlockServer`, `StarterPlayerScripts.FlockClient`.

**Доказательство (ограниченное):**

* `bash tools/check_syntax.sh` → «Синтаксис: ошибок нет (24 файлов)».
* `bash tools/smoke.sh` → «SMOKE: проверок 18, провалов 0»: клиент и сервер
  **выполняются** headless против мока Roblox API
  (`tools/roblox_mock.luau`): HUD строится (31 элемент интерфейса), мир
  создаёт 18 птиц и 48 сегментов колец, 90 кадров игрового цикла отрабатывают
  без исключений, кнопка «ПОЛЕТЕЛИ» запускает забег, клавиатура, мышь и потеря
  фокуса обрабатываются без ошибок, серверный модуль загружается.

Мок — это не Roblox: он не проверяет отрисовку, реальные ассеты и семантику
движка (см. раздел 2), но позволяет поймать ошибки **выполнения**. Именно так
был найден баг в `src/client/World.client.luau`: в `World.update` обращение
`KINDS[index]` выходило за границы массива (индекс до 54 при 6 видах) — в
Studio это был бы error каждый кадр. Исправлено (шаг хранится в самом пропсе).

## 2. Что реализовано, но не проверено (нужен Roblox Studio / сервер)

Честный список: код написан и синтаксически корректен, но **в Roblox не
запускался** (в песочнице нет Studio и нет доступа к Roblox-серверам).

1. **Визуал целиком**: птицы, кольца, мембраны, нимб, Trail, «бесконечная»
   земля, пул декораций, Lighting. Код выполняется (smoke-тест), но против
   мока API; риск остаётся в CFrame/поворотах, реальном `Enum`, поведении
   `Trail`/`LightEmission` и наслаивании прозрачности.
2. **Камера**: `CFrame.lookAt` + сглаженное слежение; в Studio может
   «дёргаться» на резких поворотах (мок не проверяет поведение камеры).
3. **HUD**: раскладка на разных разрешениях, твины, виньетка. Не проверено,
   что элементы не перекрываются на 16:9.
4. **Звук**: используются движковые ассеты (`electronicpingshort.wav`,
   `action_jump.wav`, `impact_water.mp3`, `switch.wav`, `button.wav`,
   `uuhhh.mp3`). В Roblox Studio часть из них может отсутствовать — тогда звук
   просто не проиграется (ошибок не будет, всё в `pcall`).
5. **DataStore**: `GetAsync`/`SetAsync` на `flock_best_v1` — реальных запросов
   не было; поведение при `GetAsync` с `Enable Studio Access to API Services`
   выключенным не проверено.
6. **Сетевая валидация рекорда**: `Score.isPlausible` покрыта юнит-тестами на
   чистой функции, но сам remote-протокол в Studio не прогонялся.
7. **Ввод игрока**: нормализация диагоналей и сброс залипающих клавиш покрыты
   кодом и прогоном через мок (события `InputBegan`/`InputEnded`/
   `WindowFocusReleased`), но «живую» отзывчивость в Studio не оценивал.
8. **Роблокс-API в `Game.step` не используется намеренно** — это осознанное
   ограничение: клиент авторитетен для аркадной симуляции, сервер отвечает
   только за рекорд. Взлом клиента может накрутить счёт, но не обойти
   серверную проверку скорости набора очков.

## 3. Что не сделано, заглушки, известные проблемы

### 3.1. Не сделано (осознанно, не хватило времени / вне объёма 2 часов)

* **Мультиплеер/кооперация**: игрок один, стая общая для всех, но второй
  игрок подключиться не может.
* **Мобильный ввод**: только клавиатура (тач-стик не реализован).
* **Сохраняемые настройки графики/качества**: нет, есть только фиксированный
  набор пропсов.
* **Локализация**: только русский текст.
* **Ассеты**: никаких внешних моделей/звуков — всё на примитивах Roblox.
* **Сюжет/обучение**: есть подсказка в HUD и текст на экране старта, но
  полноценного обучающего тура нет.
* **Публикация и баланс под реальных игроков**: числовые параметры подобраны
  по автосценариям, а не по playtest'у в Studio.

### 3.2. Заглушки и упрощения

* `src/client/World.client.luau` — «бесконечная» земля сделана переиспользуемым
  набором плит, которые переносятся вперёд по ходу забега; при резких
  телепортациях возможен «шов», но трасса пологая.
* Кольца рисуются 12 сегментами (не идеальный круг) — компромисс ради
  производительности при 6+ кольцах на экране.
* Звук колец/комбо реализован сменой `PlaybackSpeed` по комбо, а не отдельными
  ассетами на каждый уровень.
* `tools/probe.sh` и `tools/scenario.sh` — отладочные инструменты, не часть
  игры; в репозитории оставлены осознанно (по ним настраивался баланс).

### 3.3. Известные проблемы и риски

* **Баланс «на глаз»**: без Studio playtest'а параметры (радиусы колец,
  окна, сила ветра и камней, порог паники) могут оказаться слишком
  мягкими или слишком жёсткими. Все они вынесены в `Config.luau` и
  `Difficulty.luau` — правятся в одном месте.
* **Автопилот в сценариях не умеет собирать потерянных птиц** (это отдельный
  навык игрока), поэтому в сценарии `calm` часть птиц со временем выпадает из
  строя и счёт ниже, чем у живого игрока. Это ожидаемо, но стоит учитывать
  при чтении логов.
* **Паника зависит от резкости ввода**, а ввод в клиенте сглаживается: на
  разных клавиатурах и при разном FPS «порог нервозности» будет ощущаться
  по-разному. Порог (`Config.bird.panicBreakAt = 0.3`) вынесен в конфиг.
* **Дрейф потерянных птиц** ограничен трением (`lostDrag`), но при долгом
  забеге без сбора они уходят далеко и догнать их можно только целенаправленно.
* **Тряска камеры** использует `Random` через HUD; при большой амплитуде и
  низком FPS возможны «дёрганья» — амплитуды небольшие (0.5–0.9).
* **Серверная защита рекорда — эвристическая** (максимум очков в секунду).
  Клиент авторитетен, поэтому целенаправленный чит возможен; для одиночной
  аркады этого достаточно, для публичного рейтинга нужна серверная симуляция.
