# СТАЯ (Flock) — аркадная игра для Roblox

> Ты — **вожак** стаи из 18 птиц. Впереди — кольца-ворота, ветер, скалы и буря.
> Кольцо засчитывается, только если его прошла **вся стая**. Потерянных птиц
> нужно вернуть в строй. Главный навык — **вести вожака спокойно**: дёрганое
> управление пугает стаю, и она разваливается.

Игра написана на Luau. Вся логика симуляции — **чистый Luau без Roblox-API**,
поэтому её можно прогонять и тестировать headless (юнит-тесты + сценарные
прогоны в консоли), а Roblox-слой только рисует, читает ввод и общается с
сервером.

---

## 1. Быстрый старт

### 1.1. Проверки без Roblox (то, что можно проверить в CI)

Нужен интерпретатор Luau (собирается из исходников за пару минут):

```bash
bash tools/build_luau.sh          # соберёт luau, luau-analyze, luau-compile в /tmp/luau/build
bash tools/run_tests.sh            # юнит-тесты + smoke-тест клиента/сервера + luau-analyze (и клиента тоже)
bash tools/check_syntax.sh         # luau-compile по всем файлам src/ и tests/
bash tools/smoke.sh                # клиент и сервер против мока Roblox API
bash tools/probe.sh                # headless-прогон забега: кольца, счёт, комбо
bash tools/scenario.sh calm        # сценарий «спокойный пилот»
bash tools/scenario.sh medium      # сценарий «средний пилот» (задержка реакции, шум)
bash tools/scenario.sh booster     # сценарий «пилот с рывками»
bash tools/scenario.sh reckless    # сценарий «паникующий пилот»
bash tools/scenario.sh nervous 150 # сценарий «нервный пилот» (дрожь в руках)
bash tools/verify.sh               # ВСЕ проверки сразу + сводка
bash tools/rojo_build.sh           # сборка place-файла через Rojo (если rojo установлен)
```

Ожидаемый вывод `tools/run_tests.sh`:

```
TESTS PASSED: 72/72
SMOKE: проверок 56, провалов 0
luau-analyze: ошибок нет
luau-analyze (клиент/сервер): ошибок нет
```

Статический анализ покрывает **всё**, включая клиент и сервер: в песочнице
(`tools/prepare_sandbox.sh`) им подставляются заглушки Roblox-типов
(`Instance`, `Vector3`, `CFrame`, `Frame`, …), поэтому анализатор видит
настоящие поля структур и ловит опечатки вроде `ring.ring.id` вместо
`ring.id`.

`tools/scenario.sh` печатает состояние забега по секундам — это основной
инструмент балансировки (см. раздел 5).

### 1.2. Сборка и запуск в Roblox Studio

Нужен [Rojo](https://rojo.space/) (>= 7):

```bash
rojo serve default.project.json      # в одном терминале
```

В Studio: `File → Open → plugins/Rojo` (или «Connect to Rojo»), затем `Sync`.
После синка в дереве появится:

| Куда в Roblox | Что | Источник |
|---|---|---|
| `ReplicatedStorage.FlockShared` | вся игровая логика (чистый Luau) | `src/shared` |
| `ServerScriptService.FlockServer` | рекорды и валидация счёта | `src/server` |
| `StarterPlayerScripts.FlockClient` | ввод, камера, визуал, HUD, звук | `src/client` |

Нажми **Play**. Никаких рукописных объектов в студии не нужно — весь визуал
(птицы, кольца, «кайт», HUD) строится кодом.

Чтобы собрать `.rbxl`-подобный пакет без студии:

```bash
rojo build default.project.json -o flock.rbxlx
```

### 1.3. Публикация

`default.project.json` не содержит игровых объектов и не требует ручной
настройки. Для продакшена: `rojo build` → загрузить в place-файл, настроить
`GameSettings` (рекорды хранятся в DataStore `flock_best_v1`, заряды рывка —
в `flock_boosts_v1`).

### 1.4. Настройка магазина за Robux (обязательно перед публикацией)

В репозитории идентификаторы покупок — **нули** (плейсхолдеры), поэтому
кнопка «КУПИТЬ» честно отвечает «Магазин ещё не настроен». Чтобы включить
монетизацию:

1. В Roblox Creator Dashboard → **Store → Game Passes** — создать пять
   game pass'ов («Золотой рывок», «Ветрокром», «Форсаж», «Магнит+»,
   «Хозяйка») и **Developer Products** — один повторяемый продукт
   («Заряды рывка ×3»).
2. Задать цены (ориентир из интерфейса: 49 / 79 / 99 / 59 / 89 Robux и 25 Robux
   за три заряда).
3. Вписать полученные ID в `src/shared/ShopConfig.luau`:

   ```lua
   passes = {
       goldenBoost = 123456789,
       windproof = 123456790,
       fastStart = 123456791,
       magnetPlus = 123456792,
       calm = 123456793,
   },
   products = {
       boostPack = 123456794,
   },
   ```

4. Пересобрать и загрузить place-файл.

Сервер сам проверяет владение pass'ом (`GameplayService:PlayerHasPassAsync`)
при входе игрока и выдаёт перки; повторяемый продукт обрабатывается в
`MarketplaceService.ProcessReceipt` (Roblox сам вызывает обработчик после
оплаты — деньги списываются, а перк выдаётся сервером, клиент доверяет
только серверу).

## 2. Управление

| Клавиши | Действие |
|---|---|
| `W` / `↑` | газ вперёд (по курсу трассы) |
| `S` / `↓` | тормоз / задний ход |
| `A` `D` / `←` `→` | крен влево-вправо |
| `Space` | набрать высоту |
| `Shift` / `C` | снизиться |
| **ЛКМ** | **рывок** — короткое ускорение вожака (0.7 с на скорости 70, перезарядка 4.3 с) |
| мышь | камера (следом за вожаком) |
| **касание (слева)** | виртуальный стик: крен и высота |
| **касание (справа)** | рывок |

**Мобильный ввод:** палец в левой половине экрана — виртуальный стик (крен и
высота, вперёд стая летит всегда), касание в правой половине — рывок. Стик
рисуется прямо под пальцем и исчезает, когда палец оторвался.

Управление **сглаженное и осмысленное**: резкие рывки (особенно метание
стиком) поднимают «спокойствие» шкалы в обратную сторону — стая начинает
паниковать, птицы вырываются из строя, и часть колец остаётся недобранной.

## 3. Механики

### 3.1. Кольца-ворота
* Кольца идут вдоль трассы, у каждого свой радиус (46 → 42 → 38 → 36 по фазам),
  наклон и крен.
* Вожак пересекает плоскость кольца → открывается **окно** (grace window),
  внутри которого стая должна успеть проскочить. Пока окно открыто, кольцо
  **визуально сжимается** и краснеет — видно, сколько осталось.
* Итог: **ЧИСТО** (вся стая), **ЧАСТИЧНО** (часть птиц) или **ПРОПУЩЕНО**.
  В тосте всегда видно, сколько птиц не успело: «ЧАСТИЧНО 12/18».
* За «чистое» кольцо даётся базовые очки × комбо.

### 3.2. Рывок
* ЛКМ включает **рывок**: 0.7 с на скорости 70 ед/с против
  обычных 46. Скорость — это очки: чем быстрее летишь, тем больше расстояния
  набираешь.
* Но вожак на рывке **быстрее самой стаи** (60 ед/с), поэтому птицы отваливаются:
  кольца рядом с рывком перестают проходиться «чисто».
* Перезарядка 4.3 с после рывка. Решение «рывок сейчас или позже» — часть
  игры: рывок перед кольцом почти всегда стоит нескольких «чистых» колец.
* Индикатор — полоса перезарядки в HUD, во время рывка след вожака становится
  золотым.

### 3.3. Стая
* 18 птиц держат строй вокруг вожака: слоты расходятся назад и в стороны
  по V-образной схеме.
* Птицы быстрее вожака (60 против 46 ед/с) — стая сама догоняет его.
* Если птица отстала больше чем на 95 ед/с, она **выпадает из строя**
  (красная, мигает, над ней пульсирует маячок) и дрейфует по ветру.
* Под потерянной птицей горит **маячок** — её легко найти вдали.
* На экране появляется **стрелка** к ближайшей потерянной птице (чем дальше —
  тем бледнее) — «стая» никогда не теряется из виду.
* Когда вожак подходит ближе 46 ед/с, срабатывает **магнит**: птица сама
  тянется к вожаку. Вожак подбирает её, пролетев в 17 ед/с — птица возвращается
  в строй с бонусом очков.

### 3.4. Паника (ключевой навык)
* «Нервозность» вожака считается из резкости управления и манёвра.
* Нервозность → **паника стаи**: птицы дёргаются в стороны, а при высоком
  уровне паники — **вырываются из строя** (их надо собирать).
* Уровень паники виден в HUD («СПОКОЙСТВИЕ» / «СТАЯ ВОЛНУЕТСЯ» /
  «ПАНИКА СТАИ!»), нимб вожака краснеет, звучит крик стаи.
* Чем плавнее управление, тем больше «чистых» колец и выше комбо.

### 3.5. Ветер и фазы
Ветер сносит и вожака, и птиц; в бурю порыв бьёт **неравномерно** по птицам
(турбулентность) — стая вытягивается и рвётся, её приходится «собирать»
вниманием и курсом. Сила ветра показана стрелкой в HUD.

| # | Фаза | Что меняется |
|---|---|---|
| 1 | ШТИЛЬ | радиус кольца 46, окно 3.0 с, ветра нет, скал нет |
| 2 | ВЕТЕР | радиус 42, окно 2.6 с, ветер сносит стаю, появляются скалы |
| 3 | СКАЛЫ | радиус 38, окно 2.2 с, скалы часто и сильнее бьют птиц |
| 4 | БУРЯ | радиус 36, окно 1.8 с, сильный ветер, максимум скал |

Фазы идут по времени забега (0 / 45 / 95 / 150 с) и объявляются тостом.
Вместе с фазой меняется и «настроение» мира: небо, туман, яркость и цвет
света (`Lighting`) уходят от тёплого ясного к холодному штормовому — прогресс
забега читается даже боковым зрением, без открытого HUD.

### 3.6. Комбо и счёт
* Комбо ×1…×5: каждое «чистое» кольцо повышает множитель, частичное — не
  повышает, пропущенное — сбрасывает.
* Очки = база кольца × комбо + **бонус за собранную стаю** на чистом кольце
  + бонусы за подобранных птиц + **бонус за выжившую стаю** в конце забега
  (20 очков за каждую птицу, оставшуюся в строю).
* Рекорд хранится в DataStore (`flock_best_v1`) и **проверяется на сервере**:
  невозможный счёт (слишком много очков в секунду) отбрасывается.
* Как только счёт в забеге перевалил за личный рекорд — на экране вспышка
  «НОВЫЙ РЕКОРД!». Победить себя — главный мини-достижение игры.

### 3.7. Препятствия
Камни-«осколки» висят вдоль трассы. Птица, задевшая камень, отлетает в
сторону и может выпасть из строя. Обход камней — часть навыка.

### 3.8. Затишье (второй шанс)
Когда в строю остаётся **6 птиц или меньше**, включается «затишье» на 8 секунд:
ветер слабеет в 5 раз, камни не появляются. В HUD горит подсказка
«ЗАТИШЬЕ: ВЕТЕР СТИХ». Это шанс собрать стаю обратно — но паника от нервного
управления не проходит: если вожак продолжает дёргаться, затишье не поможет.

### 3.9. Условие проигрыша
В строю осталось **4 птицы или меньше** (и 4 секунды никто не собирался) →
стая рассыпалась, забег окончен. Итоговый экран показывает счёт и рекорд.

### 3.10. Гонка с другими игроками (общий забег)

* Сервер заводит **раунд**: генерирует сид и назначает общее время старта
  (обратный отсчёт 3-2-1). Все игроки сервера получают **один и тот же сид**,
  а значит **один и тот же курс**: раскладка колец, камней и стартовая
  формация стаи совпадают — результаты сравнимы.
* Клиент считает забег у себя (как и в одиночном режиме) и 4 раза в секунду
  отправляет серверу прогресс: счёт, дистанцию, число птиц в строю, позицию
  вожака и признак финиша.
* Сервер **не доверяет** клиенту: счёт проверяется тем же правилом
  правдоподобности, что и рекорд (`Score.isPlausible`), а длительность забега
  считает сам сервер (клиентское время берётся только как нижняя оценка).
* В правом верхнем углу HUD — **живой рейтинг**: до пяти игроков, счёт и
  подсветка своей строки. Рейтинг пересчитывается раз в секунду.
* В мире видны **«призраки» соперников** — светящиеся маркеры на позициях
  других вожаков: видно, кто впереди, а кто отстал.
* Когда игрок финиширует, сервер фиксирует **место** (порядок финиша).
  На финальном экране: «МЕСТО 2 из 4».
* Если игрок зашёл в сервер посреди забега — он вступает в текущий раунд с
  тем же курсом (догоняет с нуля, но на равной трассе).

### 3.11. Забег дня (общий курс суток и таблица лидеров)

* Кнопка **ЗАБЕГ ДНЯ** на экране старта запускает забег с **курсом дня**:
  сид выводится из даты (UTC), поэтому в течение суток у всех игроков
  **одинаковый курс** — результаты сравнимы между собой.
* **ТАБЛИЦА ДНЯ** (кнопка слева внизу) показывает лучшие результаты игроков
  за сутки; результат попадает в таблицу, только если он лучше прежнего.
* Таблица хранится в DataStore (`flock_daily_ГГГГММДД`) — у каждого дня свой
  ключ, вчерашний забег не мешает сегодняшнему.
* В забеге дня действуют обычные правила (стая, кольца, ветер, комбо) и все
  перки из магазина.

### 3.12. Магазин и перки (монетизация за Robux)

Кнопка **МАГАЗИН** (внизу экрана) открывает панель покупок. Покупки
обрабатывает сервер, клиент только запрашивает и показывает результат.

| Перк | Тип покупки | Что даёт |
|---|---|---|
| ЗОЛОТОЙ РЫВОК | game pass | перезарядка рывка вдвое короче (4.3 с → 2.15 с) |
| ВЕТРОКРОМ | game pass | ветер не сносит ни вожака, ни стаю |
| ФОРСАЖ | game pass | забег начинается с комбо ×2 |
| МАГНИТ+ | game pass | радиус подбора потерянных птиц больше в 1.5 раза |
| ХОЗЯЙКА | game pass | стая нервничает заметно меньше (меньше потерь) |
| ЗАРЯДЫ РЫВКА ×3 | developer product | три **мгновенных** рывка (работают, даже когда обычный на перезарядке) |

* Перки применяются **мгновенно** и без перезагрузки: сервер присылает
  список перков, клиент обновляет и текущий забег, и магазин.
* Заряды рывка — повторяемая покупка: их количество хранится в DataStore
  (`flock_boosts_v1`), а выдаёт их обработчик чека `ProcessReceipt`.
* Пока ID покупок в `src/shared/ShopConfig.luau` равны нулю, сервер честно
  отвечает «Магазин ещё не настроен» (см. раздел 1.4).
* Честная оговорка: покупки в Roblox Studio/на живом сервере **не проверялись**
  (нет доступа к аккаунту разработчика) — проверен только кодовый путь
  «клиент → сервер → MarketplaceService → выдача перка».

---

### 3.13. Как проверяется клиентский код

Roblox Studio в песочнице недоступна, но клиентский код можно **выполнить**
headless: `tools/roblox_mock.luau` реализует минимальный API Roblox
(`Instance`, `Vector3`, `CFrame`, `UDim2`, `Color3`, `Enum`, `TweenService`,
`UserInputService`, `RunService`, `Players`, `DataStoreService` и т.д.).
`tools/smoke.sh` на этой основе поднимает клиент, строит HUD/мир/визуалы и
прогоняет 90 кадров игрового цикла, а затем ещё 400 кадров с зажатым `W` —
чтобы вожак долетел до первого кольца и отработал путь событий кольца.

Мок — не Roblox: он не проверяет отрисовку и реальные ассеты, но ловит
ошибки выполнения. Именно так был найден и исправлен баг в `World.update`
(обращение к `KINDS[index]` выходило за границы массива — в Studio это был бы
error каждый кадр).

## 4. Архитектура

```
src/shared/      — ЧИСТЫЙ LUAU, без Roblox-API (можно тестировать в CLI)
  Vec.luau        векторы {x,y,z}
  Config.luau     все настройки игры
  Course.luau     трасса: точка/касательная/правая ось по координате z
  Difficulty.luau фазы (радиусы кольца, окна, ветер, скалы)
  Flock.luau      стая: слоты, пружина к строю, паника, сбор потерянных
  Rings.luau      кольца: появление, пересечение, подсчёт, окно
  Score.luau      очки, комбо, античит (isPlausible)
  Rng.luau        детерминированный LCG
  Obstacles.luau  камни: появление, отсев, отдача
  Game.luau       игровой цикл целиком: step(dt, input) -> события
  Race.luau       рейтинг забега: сортировка, места, поиск позиции игрока
  Perms.luau      перки (покупки): что и как меняют в игре
  ShopConfig.luau ID покупок и цены (нули = не настроено)
  Daily.luau      забег дня: сид по дате, сортировка таблицы лидеров

src/client/      — Roblox-слой (только ввод/рисование/звук)
  Input.client.luau   клавиши -> нормализованные оси
  World.client.luau   земля, пул декораций, палитра фаз (небо/туман/свет)
  Views.client.luau   вожак, птицы, кольца (след, взмах, мембрана), камни, маячки
  HUD.client.luau     счёт, комбо, стая, спокойствие, таймер, фазы, ветер,
                      окно кольца, стрелка к потерянной птице, тосты
  Audio.client.luau   звуки (всё в pcall — игра не падает из-за звука)
  Main.client.luau    цикл: Game.step -> события -> HUD/Views/Audio, рекорд

src/server/Main.server.luau — рекорды, раунд/гонка, монетизация
```

Ремоуты (создаёт сервер в `ReplicatedStorage.FlockRemotes`):

| Ремоут | Направление | Что несёт |
|---|---|---|
| `SubmitScore` / `BestScore` / `RequestBest` | клиент ↔ сервер | рекорд |
| `RequestRound` | клиент → сервер | «хочу участвовать в забеге» |
| `RequestDaily` | клиент → сервер | «хочу забег дня» |
| `DailyBoard` | сервер → клиент | таблица лидеров дня |
| `RoundStart` | сервер → клиент | сид раунда и время старта |
| `Progress` | клиент → сервер | счёт, дистанция, птицы, финиш, позиция |
| `Standings` / `RoundEnd` | сервер → клиент | живой рейтинг и итоги забега |
| `BuyPass` / `BuyProduct` | клиент → сервер | запрос покупки |
| `BuyResult` | сервер → клиент | ответ: окно покупки открыто или магазин не настроен |
| `PermsUpdate` | сервер → клиент | перки игрока (в т.ч. число зарядов) |
| `UseBoostCharge` | клиент → сервер | потрачен заряд мгновенного рывка |

Ключевая идея: `Game.step(dt, input)` — **чистая функция состояния**. Она не
знает про Roblox, поэтому:

* вся механика тестируется обычными юнит-тестами в CLI;
* можно прогнать сотни забегов за секунду (сценарии `calm` / `reckless`) и
  измерить баланс;
* клиентский слой — тонкая обёртка: ввод → `Game.step` → события → HUD/звук.

События, которые `Game.step` возвращает наружу: `rings` (исход каждого
кольца: `perfect` / `partial` / `fail`), `recovered`, `scattered`,
`phaseIndex`/`phaseName`, `boost`, `mercy`, `gameOver`.

## 5. Инструменты и как они использовались

| Скрипт | Что делает | Что доказывает |
|---|---|---|
| `tools/build_luau.sh` | собирает Luau CLI из исходников | есть интерпретатор для тестов |
| `tools/prepare_sandbox.sh` | готовит плоскую песочницу для CLI | тесты запускаются без Roblox |
| `tools/run_tests.sh` | юнит-тесты + smoke + `luau-analyze` (логика, клиент и сервер) | логика и типы корректны |
| `tools/check_syntax.sh` | `luau-compile` по всем `src/` и `tests/` | нет синтаксических ошибок в клиенте/сервере |
| `tools/probe.sh` | один забег с подробным логом колец | кольца засчитываются, счёт растёт |
| `tools/scenario.sh <режим> [сек]` | забег по сценарию пилота | баланс: спокойный выигрывает, паникующий проигрывает |
| `tools/verify.sh` | гоняет все проверки разом и печатает сводку | одна команда для финальной сверки |
| `tools/rojo_build.sh` | собирает place-файл (`rojo build`) и проверяет, что в нём есть все ожидаемые контейнеры | манифест `default.project.json` валиден, структура проекта собирается |

Пример балансировочного прогона (`tools/scenario.sh calm` / `reckless`):

```
calm    : счёт=28440, колец=36, чистых=35, живо 18/18, паника 0.05   (идеальный пилот)
medium : счёт=25560, колец=35, чистых=33, живо 18/18                   (задержка реакции, шум)
booster : счёт=29340, колец=37, чистых=36, живо 18/18  (рывок раз в 5 с)
calm 5м : счёт=77580, колец=139, чистых=115, живо 18/18
nervous: счёт=41160, колец=62, чистых=56, живо 18/18  (150 с, стая цела, но чистых колец меньше)
reckless: счёт=1020,  колец=24, чистых=0,  живо 3/18  -> ИГРА ОКОНЧЕНА
```

Сценарии — разные состояния игры: аккуратный пилот, пилот с рывками, нервный
пилот (дрожь в руках: стая цела, но чистых колец заметно меньше) и
паникующий пилот (забег срывается). Разница в результатах — и есть баланс:
чем спокойнее вожак, тем больше очков; сорвать стаю можно только постоянно
дёргая стиком.

## 6. Что проверено, а что нет

**Проверено в репозитории (команды + вывод в логах):**

* `tools/run_tests.sh` → `TESTS PASSED: 72/72`, `SMOKE: проверок 56, провалов 0`,
  `luau-analyze: ошибок нет` (логика + тесты) и `luau-analyze (клиент/сервер):
  ошибок нет`
* `tools/check_syntax.sh` → синтаксис без ошибок (32 файла)
* `tools/smoke.sh` → клиентский и серверный слои **выполняются** headless против
  мока Roblox API (`tools/roblox_mock.luau`): интерфейс строится, 18 птиц и
  кольца появляются в мире, 90 кадров игрового цикла отрабатывают, кнопка
  старта запускает забег, вожака летит по нажатому `W` и **кольцо
  засчитывается** (проверяется путь событий кольца), ЛКМ запускает рывок,
  «ЕЩЁ РАЗ» перезапускает забег, персонаж прячется, сервер принимает
  правдоподобный рекорд и отбрасывает невозможный
* smoke-тест гонки и магазина: клиент получает **сид раунда** от сервера,
  запускает забег по обратному отсчёту, сервер собирает **рейтинг** и
  **присваивает место** после финиша, в мире появляется **призрак соперника**,
  кнопка магазина открывает панель, покупка вызывает
  `PromptGamePassPurchase` / `PromptProductPurchase`, обработчик чека выдаёт
  **заряды рывка**, а владение game pass'ом присылает перк клиенту
* smoke-тест забега дня: клиент получает **режим «daily»** и **курс дня**,
  совпадающий с `Daily.seedToday()`, результат финиша попадает в **таблицу
  лидеров дня**, кнопка «ТАБЛИЦА ДНЯ» открывает панель
* `tools/verify.sh` → все проверки разом + сводка («ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ»)
* `tools/rojo_build.sh` → **сборка через Rojo проходит**: place-файл собран
  (`rojo build`, 121 КБ), в нём на месте `FlockShared` (10 модулей),
  `FlockServer` и `FlockClient` (6 модулей)
* сценарные прогоны игрового цикла: кольца, счёт, комбо, паника, проигрыш,
  детерминизм, отсутствие NaN/Inf

**Не проверено (нужен Roblox Studio / Roblox-сервер):**

* как это **выглядит**: код клиента выполняется, но против мока API, а не
  против настоящего Roblox — реальная отрисовка, свет, тени, поведение
  Trail/мембран не проверены;
* звуки: используются `rbxasset://sounds/*`; если ассета нет — звук не
  проиграется (обработано через pcall, ошибок не будет);
* DataStore и сетевая валидация рекорда: код есть, реальный запрос не выполнялся;
* **покупки за Robux**: кодовый путь проверен на моке (запрос → промпт →
  чек → выдача перка), но настоящие Robux-транзакции, окно покупки и
  обработчик `ProcessReceipt` Roblox-сервера не запускались; ID покупок в
  репозитории — нули (плейсхолдеры);
* **гонка на нескольких игроках**: проверен сценарий с двумя участниками
  (сервер выдаёт общий курс, ведёт рейтинг, раздаёт места, клиент рисует
  призраков), но реальная сетевая игра между людьми не запускалась;
* синхронизация визуала соперников: позиция соперника приходит 4 раза в
  секунду, поэтому «призрак» соперника визуально отстаёт на доли секунды —
  это осознанное упрощение, а не баг;
* забег дня: таблица лидеров хранится в DataStore с ключом по дате, но
  реальные запросы к DataStore не выполнялись; «улучшение» своей строки
  проверяется на сервере, но не на настоящем сервере Roblox;
* поведение под реальным вводом игрока: сглаживание осей проверено только
  юнит-тестами, сценариями и прогоном ввода через мок.

Подробный разбор — в [`docs/REPORT.md`](docs/REPORT.md), обоснование
концепции — в [`docs/BRAINSTORM.md`](docs/BRAINSTORM.md).
