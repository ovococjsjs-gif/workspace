# Протокол ассистента

## Жёсткие правила (не нарушать никогда)
1. **Только ветка `arena/01a09a1c-workspace`.** Не создавать, не переключать, не пушить другие ветки.
2. **Никаких merge.** Ни `git merge`, ни PR в `main`, ни rebase на другие ветки — сессия привязана к текущей ветке, слияние её ломает.
3. **Никогда не трогать** `/home/user/workspace` как путь и каталог `.git`: не удалять, не переименовывать, не переносить.
4. **Не выдумывать факты.** Не уверен — сказать прямо и предложить проверить поиском (поиск применяю только с разрешения или когда задача явно требует свежих данных).

## Анти-лаг (диффы)
Перенесено из workspace арбуза `Riyozaki/workspace` (ветка `arena/01a08101-workspace`) — там эта схема уже обкатана, см. их `docs/arena-optimization-2026-09-12.md`:
- **Глобальный `* -diff` в `.gitattributes` — сохранять всегда.** Текстовых строк в накопительном диффе нет; список изменённых путей Arena может показывать всё равно. Не выводить patch в чат и не запускать `git diff --text` по всему репозиторию — только точечно по известному текстовому файлу.
- **Не применять** reset/rebase/force-push/переписывание истории/sparse-checkout/LFS/смену базы сессии ради уменьшения диффа.
- **Быстрая диагностика:** `python3 tools/health.py` (после публикации — с `--remote --require-clean`). Скрипт не печатает patch, не чинит ref/index, сеть только при явном флаге.
- **`wc -w` в этой песочнице недостоверен** (на кириллическом файле показал 13 662 слова вместо 58 593). Подсчёт слов/знаков — только Python.
- **Не предлагать по кругу** браузер/кэш/VPN/выход из аккаунта/поддержку: арбуз это уже пробовал, результата нет. Причина зависаний не установлена; репозиторий её не объясняет.

Интерфейс Arena тормозит на большом числе изменённых файлов. Поэтому:
- **Постоянные имена, а не новые файлы.** Новые знания → в существующий раздел существующего файла.
- **Append вместо rewrite.** Дописываю блок, не переписываю файл целиком.
- **Один файл — одно изменение за ход**, когда это возможно; правки точечные (`edit_file`), не `write_file` поверх всего файла.
- **Объёмное и временное — в `scratch/`** (исключён из git через `.gitignore`).
- **Бинарники в git не кладу** никогда: картинки, PDF, архивы, датасеты, `node_modules`, `dist`, кэши.
- **Коммит — один на задачу**, коротким сообщением; не коммичу каждый чих (автосохранение платформы и так фиксирует файлы).
- **Держать «висящий дифф» пустым.** Нескоммиченные изменения пересчитываются интерфейсом каждый ход, поэтому в конце задачи — коммит, и `git status --short` должен быть пуст.
- **Никаких фоновых процессов без нужды.** Серверы и watcher'ы держать только пока идут работы, и останавливать (`stop_process`) по завершении: живой процесс = постоянное обновление превью в интерфейсе.

## Режимы диффов
Переключение — маркером `-nodiff` / `-archive` в начале сообщения владельца (или его просьбой «сделай без диффов»). Ассистент может сам предложить режим, если правка получится крупной.

- **По умолчанию.** Мелкие точечные правки существующих файлов, один коммит на задачу, `git status` пуст в конце. Дифф за ход — единицы строк.
- **`-nodiff`** — ничего не попадает в git за этот ход:
  - не пишу и не правлю трекаемые файлы, не делаю коммит;
  - расчёты, эксперименты, черновики, выгрузки — только в `scratch/` (ignored) или прямо в ответе;
  - в конце хода: что надумали/сделали текстом и предложение «забыть» или «отложить в журнал до лучших времён».
  - Предел режима: уже созданные ранее изменения он не убирает — они живут в накопленном патчсете ветки, а merge запрещён. `-nodiff` не даёт *новых* диффов, не отменяет старые.
- **`-archive`** — объёмное сначала живёт в ignored-файле, а в git переносится одним коротким коммитом, когда владелец скажет. Применяется, только если подтверждено, что ignored-файлы не видны интерфейсу (см. тест ниже).

**Порог предупреждения:** если ожидаю больше 3 изменённых файлов или ~150 строк диффа за ход — сначала предлагаю `-nodiff` или `-archive`, потом делаю.

## Открытый технический вопрос
Не проверено, исключает ли снапшот платформы ignored-файлы (в описании среды `scratch` не значится среди автоматически исключаемых имён). Тест: `scratch/arena-probe-1.md` от 2026-09-13 — если он не виден в интерфейсе, уровень `-archive` рабочий; если виден, он бесполезен и весь объём держим в git-минимуме.

## Стиль записей
- Обращение к владельцу: **Арбуз**, на «ты».
- Язык файлов: русский, имена файлов — латиница в ВЕРХНЕМ регистре.
- **Журнал — только важные решения.** Рутинные ходы в `JOURNAL.md` не пишутся: блок добавляется, когда зафиксировано надолго (правило, договорённость, изменение структуры). Формат блока: `## YYYY-MM-DD — тема` → «решили / почему / что изменилось».
- В `NOTES.md` каждый раздел начинается с `# Раздел`, записи внутри — с даты.
- Утверждения «не знаю / не уверен» фиксирую честно, а не сглаживаю.

## Что я делаю без напоминания
- В начале большой задачи — уточняющий вопрос, если двусмысленность меняет результат.
- В конце задачи — запись в `JOURNAL.md` (2–5 строк), если было что решить или сделать.
- Перед коммитом — `git status --short`, чтобы в коммит не улетел мусор.
